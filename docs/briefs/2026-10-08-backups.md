# Backups — 8 Oct 2026 (decision #6)

**Decision:** how to back up the database and its files, and where the copies are kept.
**Recommendation:** B — a nightly copy of the whole database and its files to a separate private GitHub repository,
checked automatically by restoring it each night. The Supabase paid plan stays decision #17.

*Columns adapted for a non-game decision: protection instead of growth, real money instead of game profit.*

| Option | Protection | Cost a month | Opportunity cost | Risk | Easy to undo? |

## Background
- **No backups today.** The database is on Supabase's free plan (organisation "Equinox Alliance", plan: free).
  Supabase backs up only paid projects and tells free projects to export their own data and keep it off-site
  (supabase.com/docs/guides/platform/backups).
- **The planner is one row.** `planner_state` (288 kB) holds every plan card, to-do, aircraft, frequency, delivery,
  interline note and the fare plan. Every save overwrites it; there is no earlier version.
- **Size:** 20 MB in all. Largest tables: report PDFs (2.7 MB), bank statements (2.0 MB), world-scan snapshots
  (1.4 MB), capture pages (0.4 MB). Plus 57 files (2.9 MB: photos, logos) in Storage, which database backups never
  include, even on the paid plan.
- **Code is already safe** in GitHub since decision #1. The capture history (loads, statements, events) exists only
  in the database, and it feeds route profit, the cash forecast and the weekly report.
- **What B would do:** each night after the capture, a GitHub Action dumps the whole database (all tables, sign-in
  users, the migration record) as plain SQL, downloads the Storage files, and commits both to a private repository
  `equinox-backups`. It then loads the dump into an empty Postgres to prove it restores, and counts the rows. Each
  night's result (done or failed) is reported where you'll see it; how exactly is part of the build. It is kept separate from the code repository, because the code repository never holds live data.
- **What you'd do once:** create the empty private repo `equinox-backups`, and paste the database connection string
  (Supabase → Project settings → Database) into that repo's secrets. It never passes through chat.

## Scenarios and the risk of waiting
- **A bad save** (an old tab overwrites the planner): with B you lose at most that day's edits; with nothing you lose
  everything. Decision #15 (keep every change) closes the same-day gap later.
- **Supabase account or project problem:** only B (or C) has a copy outside Supabase.
- **Waiting:** until a copy exists, a single mistake loses the plan cards, to-dos and the capture history behind
  route profit and the forecast. This morning's workspace reset showed how that happens.

## What would change the recommendation
- Needing database copies to test changes on (decision #8) or wanting in-place restores in minutes: then the paid plan
  is worth it sooner, and #17 should come right after.
- GitHub becoming unsuitable for the data (for example, sharing the planner with other players): then switch the
  destination to separate storage such as Cloudflare R2.

## Outcome
**8 Oct 2026: B decided.** No spending on Supabase's paid plan. Checked first: the GitHub Student pack has no
Supabase or Neon offer; its Heroku, Azure, Appwrite and MongoDB credits would each mean rebuilding sign-in, storage and
the data API, and they expire. The site's files sit in one public bucket, so the job needs only the database
connection string as a secret.

**Live 8 Oct 2026, 20:30 UTC.** First backup: 21 tables, 6,337 rows and 57 files (5.5 MB dump, 3.0 MB files), restored
into an empty database with every row count matching; no key tables or sign-in data in the copy. Runs nightly at
07:17 UTC; results in `backup_runs`, shown on the planner.
