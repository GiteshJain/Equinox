# Planner

One part of the map, `docs/architecture.md`, in full. The map has the short version; a build that changes this part adds its dated note here, not in the map.

## What it is

The staff tool, rebuilt in React with TypeScript (#18), screen by screen beside the old one, and **the planner at `/planner/` since the switch** (14 Oct, build pull request 13; design `docs/design/2026-10-12-planner-app.md` §11): every address under `/planner/` opens it, the addresses used while it was built (`/planner/next/...`) redirect (301) to the same address under `/planner/`, and the old planner's (`/planner/old/...`) to `/planner/`, since the clean-up (build pull request 14) removed the old planner, its adapter and its documents. The shell (build pull request 1): sign-in and the staff check (`is_planner_user()`), the header (brand, the search box, local/UTC toggle, save state, the Website button, sign-out) with the game clocks under it on every screen (one per time zone of our bases, from the library's `time.clocks`; the old planner's band of the UTC day is there too, hidden as the old planner hides it), the screens' navigation (ten since 21 Oct); Home (build pull request 5, below), Routes (build pull request 6, below), Tails (build pull request 7, below), Hubs (build pull request 8, below), Check (build pull request 9, below), Review (build pull request 10), and Interline, Photos, Reference and the header's search (build pull request 12, below): every screen is rebuilt.

**Since 20 Oct the screens are grouped by when they're used** (spec `docs/specs/2026-10-20-today-performance-systems.md`): Home, Today, Routes, Tails, Performance, Competition (since 21 Oct), Interline, Photos, Reference and Systems; Check's and Review's boards moved to Today, Performance and Systems, and Hubs went (below). It reads the tables straight through supabase-js, with types generated from the database (`app/planner/src/db/types.ts`) and TanStack Query, and the database functions that only read with GET (so a preview reads them too), and writes only through `planner_save()`: one call per action, all or nothing (an insert may name the row it makes, and a later change in the same call take its key, so a to-do and its steps are one action).

**Its start is light** (design §5): the planning library's input is `rules_input(world, 'flown')`, only the routes that have rotations and the airports they, the legs, the bases and the aircraft use (`'all'`, about 1 MB on live, stays the scripts').

**Home** looks and works as the old Home (the Building chat's review): the operations hero with the globe, needs attention's summary cards (since 23 Oct, spec `docs/specs/2026-10-23-attention-on-home.md`: one card per thing waiting, exactly as Today showed them, each **See all** opening its group's section on Today at `/planner/today#att-<kind>`; Home only shows them: the reads and figures are Today's, `screens/today/useAttention.ts`, shared through the query cache, and the words `today/model.ts`'s `waitingCards`), the network map and the airline cards. Aircraft on order went from Home the same day (Today's Orders and delivery lines show it; `onOrder.ts`, which Aircraft to file still uses, moved to `screens/today/`). Its needs attention (with the old Home's interline line since the switch: the airline–country pairs Interline lists without an agreement, from the same rows, `screens/interline/useRows.ts`, and `interline_agreements`), coming up, the to-do board and aircraft on order's **File into planner** moved to Today on 20 Oct (below), with the sources of theirs listed here.

**Since 30 Oct each airline card has its profit over the last 14 reports** as a sparkline (part C; `airline_profit()`, Performance's read, `figures.ts`' `profitSpark()`).

**Its sources** (#19, one home each): from the planning library on that input, the key figures (`summary.keyFigures`), the hero's figures (`summary.now`: aircraft in the air, flights today and in the next hour), the aircraft's positions (`positions`), each airline's card (`summary.airlineCards`), each route's round trips on the map (`summary.roundTrips`) and the schedule checks (maintenance, turns and positions, night bans, flight numbers used twice, the airport caps from `airport_cap_warning_pct`); from the database, the capture warning from `capture_status()` (asked at the moment and a day earlier, reaching back to midnight UTC two days ago as the old Home did; and, since #21, a short or broken page the same night, from each airline's latest verdicts), the backup and job warnings from `backup_runs` and `job_runs`, the group's average economy load and can order from `airline_cards()`, routes to fix (and, with no profit captured, the load patterns) from `growth_signals()`, and each route's loads with one airline picked on the map from `route_loads()`; aircraft on order, plan cards (the map's Planned routes), to-dos and dismissals from their tables; the hub-city photos from `site_public()` (each airline's city from `airlines.photo_city`). The globe is three.js (pinned in `package.json`), loaded only on Home, with the old planner's earth pictures (three-globe's, from cdn.jsdelivr.net); the map draws the website's world outline (`web/assets/world.js`) and the cards its logos (`web/assets/logos.js`), each read from `/assets/`.
