# Database

One part of the map, `docs/architecture.md`, in full. The map has the short version; a build that changes this part adds its dated note here, not in the map.

## What it is

Supabase project `ulecwsyedvwcxgdzmhoq` (free plan): 74 tables, 8 views and 54 functions in `public`, 144 internal functions in `private` (which the data API doesn't expose), staff sign-in, and the `site-photos` file bucket. 35 of the tables are the planner's data in proper tables (#13: worlds, airlines, aircraft, routes, flight legs, plan cards, to-dos, settings and more; the 33rd, `airline_order_cabins`, since 15 Oct; the 34th and 35th, `plan_lines` and `plan_line_legs`, since 28 Oct: the 7-day lines, each with its legs by line day, and a plan card's `line_id` and `line_day_offset`, one card per line and offset among aircraft that aren't retired, kept by `private.plan_line_slot()`; spec `docs/specs/2026-10-27-long-haul-lines.md` §2), loaded from the old planner's storage (#13, pull request 4), and the truth since the switch-over (pull request 9). The planner writes through `planner_save()`: one call per action, all or nothing, refused if any row it changes was changed elsewhere since it was read (its `updated_at`), only the 35 planner tables, actor planner with the tab's ID. Other chats write through it too, or plain SQL after the `equinox.actor` line (manual §1). The old planner's documents (`planner_state`, `planner_loads`, `planner_meta`, `planner_data`), the adapter that read and wrote them, and the tables #13 renamed and kept went with the clean-up (build pull request 14). Every change to the tables is recorded in `change_log`, with who made it. The rule numbers are rows too (`settings`, `world_rules`), and nothing else holds a copy. The capture's data is in the new model already: one row per flown flight (`game_flights`) and the payments not tied to a flight (`game_payments`), each with its world and airline. The daily history is kept for good (#15, #13 pull request 6): `airline_days` (each airline's fleet, schedule and cash each evening, and each UTC day's flights, passengers, money and payments) and `route_days` (per route, direction and day; since 22 Oct also each cabin's passengers and seats, the business fare and the block minutes, filled back for every day `game_flights` held), filled back to 29 Sep. The world scans are `game_scans` and its tables, with each airline's totals and its departures per airport and per market kept for good (`scan_airline_airports`, `scan_airline_markets`), and since 23 Oct each airline's fleet by type and its overview page's figures (`scan_airline_fleet`, `scan_airline_profile`: RLS on with no rule, read through functions only; spec `docs/specs/2026-10-23-rival-fleets.md`), and since 23 Oct each rival's one-stop connections on our pairs, worked out at the scan's finish (`scan_rival_connections`, by rival, pair, direction and connecting airport, detail the monthly archive takes with the scan schedules; `scan_rival_connections_week`, by rival and pair, kept for good; both RLS on with no rule; spec `docs/specs/2026-10-23-rival-connections.md`); since 21 Oct the evening capture fills them when a scan is due (`capture_scan()`), and `gscan.py` by hand through `ingest_snapshot()` is the fallback, both through `private.scan_ingest()`. Two jobs run inside the database on Supabase's scheduler (`pg_cron`, #13 pull request 7): the 10:00 UTC snapshot fallback and the 10:20 UTC clean-ups. Every job's runs are in `job_runs` (the nightly backup's too: `backup_runs` is now a view of it). Each capture page's check (#21) is kept on its raw page (`game_capture_raw.verdict`, `verdict_note`, `verdict_facts`; the limits `capture_loads_min_share` and `capture_statement_min_share` in `settings`), and `system_status()` gives the Systems board's figures (#23).

**The fleet** (since 22 Oct, spec `docs/specs/2026-10-22-fleet-capture.md`): `game_fleet` keeps each of our aircraft as the game's fleet pages show it, one row per aircraft per capture day (condition, maintenance, seats Y/C/F, pilots, location, flight, owned, contract, its fleet), the latest capture of the day winning, kept for good (about 140 rows a night: what fitting the planner's maintenance figure to the game will learn from); `fleet_checks()` lists what needs a look on the latest night. Since 22 Oct each aircraft says whether it came new or used (`aircraft.acquired`, manual §3; no default since 26 Oct, #104), which decides its replacement age (`settings.replace_new_years`, `replace_used_years`) and `fleet_checks()`'s replacement warning (`replace_warn_days`). Since 27 Oct the aircraft evaluation script's run list and results (`aircraft_eval_runs`, `aircraft_eval_results`: RLS on, staff read only; written only by `capture_eval_result()`).

**The market pages** (since 30 Oct, spec `docs/specs/2026-10-30-market-pages.md`): each run (`market_runs`, kept for good), each page read (`market_reads`, with our service profile on the pair), each airline's fares by class on it (`market_fares`, nothing per flight), the game's passenger and cargo shares (`market_shares`) and each pair's weekly seats and price (`market_weeks`, kept for good), and since 4 Nov (spec `docs/specs/2026-11-04-fare-default-from-market.md`) our airline's current and default price by class from the page's Pricing panel (`market_prices`, which `default_prices()` and the fare ladder read); reads, fares and shares are detail the monthly archive takes after a full calendar month, the reads after their fares and shares, and a read's prices go with it (their key cascades; the archive doesn't list `market_prices`). All six RLS on, staff read only; written only by `capture_market()`.

**Shared pairs** (since 5 Nov, spec `docs/specs/2026-11-05-shared-pairs.md` §1, built in #137 and #138; in force, manual §2): a joiner's `routes` row names the owner's in `routes.shares_route_id` (same world by its foreign key, same two airports and another airline by the trigger `private.check_route_share()`, one level of joining, one joiner an owner); `join_pair()` adds it (staff only, the planner's save lock, actor-logged with detail join_pair), refusing a pair that isn't base to base, Ryanair (`settings.shared_pairs_excluded_airlines`), a second joiner and, for `shared_pairs_limit_days` (14) from `shared_pairs_from`, more than `shared_pairs_limit` (6) joined pairs; the view `shared_pairs` lists every base-to-base pair of two of our airlines with its owner (the airline whose row exists, else the country rule's, a values list in the view), joiner, routes and flights a week. The fare ladder (`private.fig_fare_ladder()`) judges a joined pair once, on the owner's rows, counting the joiner's captured flights; the joiner's rows follow the owner's level and list only set-backs. Since 30 Oct (part 2, spec `docs/specs/2026-10-30-market-pages-planner.md`) the planner reads them through `route_story()`, `competition()` and `market_service_checks()`, and the weekly report through `export_for_report('figures')`. Nothing signed out can read any table or view; the website, the investor page, the capture, the fares userscript, the aircraft evaluation userscript and the scripts go through functions.

**The stored figures** (since 11 Nov, spec `docs/specs/2026-11-11-stored-figures.md` §1; to-do 223): `planner_figures`
(one row per stored answer: world, kind (the function), key, the answer, its moment, its generation, how long it took)
and `planner_figures_state` (one row per world: the generation the planner should load, when it was ready, what it was
worked out from, the route pages done of the routes flown, the last error). RLS on, staff read only, nothing for anon;
written only by `private.figures_refresh()` and `private.figures_routes()`, run by a fifth job on `pg_cron`,
`equinox-figures`, every minute (the others: the 10:00 UTC snapshot fallback, the 10:20 UTC clean-ups, and the
unattended capture's start and its answer). Only the latest set is kept, replaced in place: about 5 MB of figures and 21
MB of route pages before compression, up to about twice that with the dead rows autovacuum hasn't reused yet;
`system_status()`'s usage lists the table's size (amber from 50 MB). Settings `figures_capture_quiet_min` (5),
`figures_route_budget_s` (40) and `figures_landing_max_min` (30, for the planner's landing page in part 2).
