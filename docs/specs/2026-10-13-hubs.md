# Build spec: the new planner's Hubs screen (#18 build, pull request 8) — 13 Oct 2026

**Why:** step 8 of the build order (`docs/design/2026-10-12-planner-app.md` §13). Hubs shows one airport's day and week:
every departure and arrival of all six airlines, against the hub's bank windows, and which city pairs connect there.
Home (pull request 5), Routes (6) and Tails (7) set the pattern: same features and look as the old screen, every figure
from its one home, proven side by side. The game is paused and the old planner frozen (manual §1): **nothing in
`web/planner/` changes.**

**Outcome when done:** `/planner/next/hubs` does everything the old Hubs does, on a phone too. It only reads; nothing
on it saves.
- **the toolbar:** every base and focus city, the seven days, and the count line (departures and arrivals that day,
  departures a week against the airport cap with **over cap**, the next free flight-number pair and the last used);
- **a focus city's note** (no banks of its own; timed to its hub's banks);
- **the day strip:** bank windows (arrival and departure) and a tick for every flight, with the hourly bars below;
- **the week grid:** 15-minute slots, local time, departures over arrivals, shaded by the bank windows. It scrolls
  inside its own box on a phone;
- **the flight list:** time, direction, flight, to or from, aircraft, and the bank pill;
- **connections:** by bank and outside the banks, the airports arriving and leaving with their regions, the city pairs
  (each once, at its shortest connection) and examples, across all six airlines.

## What to build
The design is the specification: §2, §4 to §7, §9 (Hubs' row), §10, §14. The old Hubs is the reference: `renderHub`,
`hubBoard`, `hubConnections`, `regionOf`, and the library parts they call (`bankWindows`, `waveAt`, `onward`,
`isFocus`, `nextPair`) in `web/planner/index.html`. Where the design and this spec disagree, stop and say so.

- **Figures from the library (`lib/rules/`):** add `hubBoard` (the day's list and hourly counts, the week grid, departures
  a week) and the connections table there, with cases, built on the existing `banks`, `connections` and `schedule`.
  Nothing on the screen works out a figure itself. Airport regions come from the data the library already has; if the
  old `regionOf` list isn't in the database, say so in the pull request rather than copying it into the screen.
- **Data:** the start's rules input (`rules_input(…, 'flown')`) should hold everything Hubs needs. No migration is
  expected; if one is needed, add only, and say why.
- **The screen** (`app/planner/src/screens/hubs/`): shared parts from `src/ui/`. Addresses `/planner/next/hubs` and
  `/planner/next/hubs/<airport>?day=<0-6>`, so a link reopens the same board. Wherever Home or Routes link to a hub's
  board, they open here instead of the old planner.
- **Phones:** at 380 px the page never scrolls sideways; the week grid and the strip scroll inside their own box.
- **`data-figure` names** on every figure.

## Checks
- **Unit tests:** `hubBoard` (a return landing the next day counts on the right day and slot; a focus city has no
  banks), the connections table (shortest connection kept, the window from the airport's MCT to
  `connection_max_wait_h`, a pair back to where it came from left out).
- **In the rehearsal, `tests/hubs_side_by_side_test.py`,** at a frozen moment, both planners as the test staff user:
  for every base and focus city, on every day, the count line, the bank windows, the hourly bars, the week grid, the
  flight list and the connections table equal the old ones'. A preview address shows Hubs. 380 px with screenshots
  (`hubs-screens` artifact).
- `tests/planner_next_test.py`: Hubs is no longer a placeholder.
- Keep the run under 30 minutes; sample days if needed and say so.

## Proving it
- `bash tests/run_all.sh` passes; the rehearsal passes with every step `ok`; screenshots attached.
- **A deliberate failure,** seen to fail then removed: connections allowed up to 9 hours instead of the setting (a unit
  test and the side by side must go red).

## Rules for the helper
- Follow `CLAUDE.md`. Reuse Home's, Routes' and Tails' code (`app/planner/src/`) and their side-by-side tests.
- **Work lean:** check on GitHub runs every few minutes rather than continuously, and don't read beyond what the build
  needs. The old planner is one large file: search for the functions named above.
- **Never connect to the live database or use the Supabase connector tools.** Don't change `web/planner/` or
  `web/assets/`.
- If a figure differs from the old Hubs, find the cause; report a real difference as a finding.
- Work on branch `hubs`, open the pull request with the REST API, and don't merge.

## Done when
Every proof is `ok` and the deliberate failure was seen to fail, then removed. The pull request says what changed, the
run time, any finding, the steps after "merge", and how to roll back.
