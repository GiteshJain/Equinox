# Build spec: the new planner's shell (#18 build, pull request 1) — 12 Oct 2026

**Why:** step 1 of the build order in `docs/design/2026-10-12-planner-app.md` §13, approved by Gitesh on 12 Oct (pull
request #26). Everything after it (the library, the database figures, the screens) builds on this shell. The game is
paused and the old planner frozen until the switch (manual §1), so **nothing in `web/planner/` changes.**

**Outcome when done:**
- `equinox-alliance.com/planner/next/` opens the new planner: sign-in, the staff check, the header (brand, local/UTC
  toggle, save state, sign-out) and the nine screens' navigation. Each unbuilt screen says so and links to the old
  planner at `/planner/`.
- The shell reads real rows straight from the tables, with types generated from the database, and saves through a new
  function, `planner_save()`, all or nothing per action, with a clash check on `updated_at`.
- Look-only previews: saving works only on `equinox-alliance.com` and `www`.
- New checks: type check, lint, unit tests and the build on every pull request; in the rehearsal, the types compared,
  sign-in, real saves through `planner_save()`, previews and phone width.
- The old planner, the website and every existing check work exactly as before.

## What to build
The design is the specification: §3 (code layout, build, addresses), §4 (sign-in, previews, access), §5 (reading,
types), §6 (saving), §10 (checks), §14 choices 3, 4 and 6. Where the design and this spec disagree, stop and say so.

### 1. The project (§3)
- Root `package.json` with a lock file (`npm`), and `.nvmrc` with `22`. Scripts: `build` (the new planner into
  `web/app/`), `typecheck`, `lint`, `test`. Pin exact versions: React 19, TypeScript, Vite 8 with React's plugin,
  React Router, TanStack Query, `@supabase/supabase-js` (the current 2.x), Vitest, ESLint with
  `eslint-plugin-react-hooks`. Nothing else unless the pull request says why.
- `app/planner/` with `index.html`, `vite.config.ts` (`base: "/app/"`, `outDir` → `web/app`, emptied on each build),
  `tsconfig.json` (strict), and `src/` laid out as §3 says: `screens/` (one folder per screen), `data/`, `ui/`,
  `db/types.ts`.
- `.gitignore`: `web/app/`. `lib/rules/` is pull request 2's; don't create it.
- **The build must be the same everywhere:** Cloudflare runs
  `if [ -f package.json ]; then npm ci && npm run build; fi` (Gitesh sets that in Cloudflare before this merges, so
  this pull request's preview shows the new planner), the checks run `npm ci && npm run build`, and the output folder
  stays `web`.

### 2. Addresses (§3)
- `web/_redirects`: the two new lines above the old ones, exactly as §3 shows. Cloudflare's redirects win over files,
  so the new planner's files must stay under `/app/`; only its page is mapped.
- `web/_headers`: `/app/assets/*` cached a year (`public, max-age=31536000, immutable`); `/app/index.html` and the
  `/planner/next` addresses uncached, like `/planner/*` today.
- `tests/harness.py`'s server follows the same rules, so the checks see what Cloudflare serves: `/planner/next/` and
  anything below it give `web/app/index.html`, `/app/...` gives the files, `/planner/` still gives the old planner.

### 3. The shell (§4, §9's look)
- **Sign-in:** email and password through Supabase's sign-in, then `is_planner_user()`. A signed-in account that isn't
  staff is signed out with the old planner's message. No sign-up form (#11).
- **Header:** the brand as the old planner shows it, the local/UTC toggle (default from `settings.planner_time_mode`,
  remembered on the device), the save state ("saved", "saving", "not saved · retry", or "preview · not saved") and
  sign-out.
- **Navigation:** Home, Routes, Tails, Hubs, Check, Review, Interline, Photos, Reference, in that order, as React
  Router routes under `/planner/next/` (`/planner/next/routes` and so on). Each screen, until it's built, shows its
  name, one line saying it's still in the old planner, and a link to `/planner/`.
- **Proof that reading works:** Home's placeholder lists the world's airlines from `airlines` (name and colour, in
  their `position` order) and the time of the latest change in `change_log`. Nothing more on screen.
- **Look:** the old planner's colour tokens, fonts (Archivo, Manrope, Unbounded) and header styling, in a shared
  stylesheet under `src/ui/`. Copy the tokens from `web/planner/index.html` (search for `:root{`); don't change that
  file.
- **Phones:** at 380 px wide, nothing scrolls sideways; the navigation fits (a scrolling row or a menu, your call, said
  in the pull request).
- **Errors:** a failed read shows its message on the screen, never a blank page.

### 4. Reading (§5)
- One Supabase client in `src/data/`, with the live address and public key the old planner uses.
- `src/db/types.ts` generated by `supabase gen types typescript` from last night's copy, after this pull request's
  migration, and committed. See §7 for how the rehearsal makes it and checks it.
- TanStack Query for every read, with one place that sets how long data stays fresh. Reads use the generated types;
  no `any` for table rows.

### 5. Saving (§6)
**The database function** (a new migration in `database/migrations/`, with a description on the function):
`planner_save(p_changes jsonb, p_client text) returns jsonb`.
- `p_changes` is a list of changes: `{table, op, key, base, values}`. `op` is `insert`, `update` or `delete`; `key` is
  the row's primary key as JSON; `base` is the row's `updated_at` as it was loaded (required for update and delete);
  `values` holds the columns to set (insert and update).
- One transaction. Actor `planner`, `p_client` (the tab's ID) as the actor detail (design #13 §6).
- **All or nothing:** if any update or delete finds the row's `updated_at` different from its `base`, or the row gone,
  nothing is written and the answer is `{ok: false, clashes: [{table, key, current}]}`, with `current` the row as it is
  now (or null if it's gone). Otherwise `{ok: true, rows: [{table, key, updated_at}]}`, inserts included.
- **Only the 32 planner tables** that carry the change-log trigger, on a list in the function. Anything else is
  refused with a clear error. Columns are checked against the table; unknown columns are refused. The tables' own
  checks still apply.
- **Access:** staff only (`planner_users`), runs as owner with an empty search path, `execute` granted to
  `authenticated` only. Follow `planner_state_put()`'s pattern (`database/current/functions.sql`).
- A test in `database/tests/` (`planner_save_test.sql`): one insert, update and delete each, read back and logged as
  planner with the client; a clash on one of two rows writes neither and returns the clashing row; a deleted row is a
  clash; a table not on the list, an unknown column and a missing base are refused; signed out and an account that
  isn't staff are refused; `updated_at` moves on each change.

**In the planner:** `src/data/save.ts` sends one call per action, shows the save state, and on a clash puts the
returned rows back into the screen's data, with a message naming what changed. On a failed call (no network) the
change stays on screen as "not saved · retry"; nothing is kept on the device (§14, choice 3). On a preview address it
sends nothing and shows "preview · not saved".
- Until screens exist there's no button that saves, so the shell exposes `window.__eqPlanner.save(changes)` for the
  rehearsal's test to call. Say in the code that it's for the checks.

### 6. Previews (§4, #8)
The same rule as the old planner: saving only when the address is `equinox-alliance.com` or `www.equinox-alliance.com`.
Everywhere else, reads work and writes never leave the page.

### 7. Checks (§10)
- **`tests/run_all.sh`** gains one check, "New planner: types, lint, unit tests, build": `npm ci`, `typecheck`, `lint`,
  `test`, `build`. Unit tests (Vitest) cover the preview rule, how a save answer is applied (ok, clash, failure), and
  the address mapping for each screen. `checks.yml` already has Node 22.
- **The website check** (`site_test.py`) still passes, and a new step opens `/planner/next/` on the local server: the
  sign-in form shows, `/app/` files load, no errors; `/planner/` still opens the old planner.
- **The rehearsal** (`database-rehearsal.yml`, `database/rehearse.sh`):
  - also runs when `app/**`, `package.json`, `package-lock.json` or `.nvmrc` change;
  - builds the new planner;
  - **types:** after the migrations, regenerates `src/db/types.ts` from the copy with the local Supabase CLI and
    fails if it differs from the committed file, printing the difference and keeping the generated file as the run's
    `planner-types` artifact (so a helper can fetch it with the REST API and commit it);
  - **a new test, `tests/planner_next_test.py`,** the new planner at its live address on the local copy, as
    `real_saves_test.py` does it (same test users, same request mapping, same "nothing goes outside" rule):
    1. signs in through the new form as staff; the account that isn't staff is refused and signed out; opening it
       writes nothing (no `change_log` row);
    2. Home's placeholder shows the copy's airlines in order;
    3. `window.__eqPlanner.save()` ticks the first open to-do: exactly that row changes (`done`, `done_at`), logged as
       planner with the tab's ID;
    4. two tabs load the same to-do; the first changes its title, the second's change to the same row comes back as a
       clash with the first's title, and the second's change to another row in the same call isn't written either;
    5. a preview address sends no write;
    6. at 380 px wide, Home's placeholder and every placeholder screen have no sideways scroll and no errors;
  - **the time limit stays 30 minutes;** say in the pull request how long the run took.
- Every earlier check and database test still passes, unchanged.

## Rules for the helper
- Follow `CLAUDE.md`. Read `.claude/skills/supabase-postgres-best-practices/SKILL.md` and its rule files for the
  migration. Read `tests/real_saves_test.py`, `tests/harness.py` and `database/rehearse.sh` before writing the new test.
- **Never connect to the live database or use the Supabase connector tools.** Test by pushing and reading the
  *checks* and *Database rehearsal* results. Docker is available here.
- **Don't change `web/planner/` or `web/assets/`.** The old planner is frozen (manual §1).
- Work on branch `planner-shell`, open the pull request with the REST API (GraphQL is blocked), and don't merge.

## Done when
- Every proof above is `ok`, and the deliberate failure was seen to fail, then removed.
- The pull request says:
  - what changed;
  - the run time of the rehearsal;
  - the steps after "merge", in order: the migration applied to live by Claude, then the live migration record set
    to its version (manual §1);
  - how to roll back: revert the pull request, then drop `planner_save()`;
  - anything outside the repository that needs a follow-up.
