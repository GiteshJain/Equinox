# Build spec: the switch — /planner/ opens the new planner (#18 build, pull request 13) — 14 Oct 2026

**Why:** step 13 of the build order (`docs/design/2026-10-12-planner-app.md` §11 and §13). Every screen is rebuilt and
proven side by side, and Gitesh tried the new planner on 14 Oct ("all looks good"). The switch makes `/planner/` the new
planner, keeps the old one reachable as a way back, and moves game changes to the new planner.

**Outcome when done:**
- **`/planner/` and every address under it open the new planner**, with its own addresses (`/planner/routes`,
  `/planner/review/VS`, …). The new planner's base address becomes `/planner/`.
- **`/planner/next/…` addresses still work:** each redirects (301) to the same address under `/planner/`, so links and
  bookmarks made during the build keep working.
- **The old planner opens at `/planner/old/`,** exactly as it is: its file's content doesn't change (manual §1: the old
  planner's code is frozen until the clean-up). Prefer serving the existing file there by `_redirects`; if it has to
  move, it moves byte for byte, and the pull request says why.
- **Going back is one `_redirects` change,** written out in the pull request and the planner guide.
- **No link in the new planner leads into the old one** any more (anything still pointing at `/planner/` for an old
  screen points at the new screen). Search the repository for other links to the planner (the website, scripts, tools,
  docs, the capture) and update any that assumed the old planner.
- **Home's interline line** in "needs attention", as the old Home has it, reading the `interline_rules` setting (design
  §16, found by pull request #37); side by side with the old Home.
