# Build spec: the clean-up — the old planner and its adapter go (#18 build, pull request 14) — 14 Oct 2026

**Why:** the last step of the build order (`docs/design/2026-10-12-planner-app.md` §12 and §13). The switch is live since
14 Oct (#38): `/planner/` is the new planner, and the old one at `/planner/old/` is only the way back. Gitesh asked for
the clean-up the same day. After it there is one planner, one way of saving, and no copies to keep in step.

**Outcome when done:**
- **The old planner is gone:** `web/planner/index.html`, its checks (`tests/planner_test.py`, the old real-saves test),
  the rule-number cross-check (`tests/rule_numbers_test.py`), and `/planner/old/` (it now redirects, 301, to
  `/planner/`).
- **The adapter is gone:** `planner_state_get()`, `planner_state_put()`, `planner_loads_get()`, `save_loads()`,
  `planner_state_version()`, `planner_item_put()`, `planner_item_delete()`, the freeze and side-by-side functions, and
  `export_for_report('planner')`'s old-format documents. So are the tables `planner_state`, `planner_loads`,
  `planner_meta`, `planner_data` and the renamed old tables (#13 design §3.13).
- **The old planner's leftovers in the data are cleared:** the hidden copy of plan-card legs (`plan_cards.extra.legs`),
  the old lists' positions in `aircraft.extra` (`tails_index`, `deliveries_index`, `delivery`) and anything else only the
  adapter read. The new planner must not need any of them first. Check and say so.
- **Nothing else breaks:** search the repository, the database (functions, views, jobs, `pg_cron`), the capture, the
  scripts, the website and the backup and archive jobs for every name being removed, and move or remove each use.
  The backups and archives must still run, and still restore, without the removed tables.

## Part 2: two fixes kept for after the switch (design §16)
1. **Hubs gives some arrivals a bank they can't make** (329 a week, found by #34): an arrival is labelled with a bank only
   when it can connect to that bank's departures within the connection rules; otherwise "outside the banks".
2. **Event and load times ignore an airport's UTC correction** (`world_airports.utc_offset_override`, found by #29):
   the captured figures use the corrected offset, as the schedules do. No airport has a correction today, so no figure
   should move. Say so if one does.

Leave design §16's other items for later, and list what's left there.

## What replaces the side by sides
The side-by-side tests compare with the old planner, which goes. Before removing them, keep what they prove in checks
that don't need it:
- **every screen** opens on last night's copy at a frozen moment with no errors, at 1280 and 380 px with no sideways
  scroll;
- **every kind of save** each screen has still writes exactly the rows the side by sides proved (record those rows as
  expected answers from the last green run, so a change to them fails);
- **the figures** stay guarded by the library's cases, the captured figures' tests and the saved answers already in the
  repository; add saved answers for any screen figure not already covered, on a fixed, dated sample.

Choose the lightest way that keeps all three, explain it in the pull request, and keep the rehearsal under 30 minutes
(it should get shorter).
