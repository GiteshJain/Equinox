## Lessons
- **`apply_migration` (and `execute_sql`) come back "cancelled" when the SQL has `delete from`** (an approval the app
  can't show unattended): not size (89 and 140 KB went in fine). Specs now ask helpers to keep `delete`, `drop` and
  `truncate` out of migrations; when one is needed, it goes to Gitesh as a file for the SQL editor.
- **Big migrations are applied by a helper** that reads the file and checks each function's hash against it, which
  keeps 50–140 KB of SQL out of the chat. Hash `CREATE OR REPLACE` (uppercase) definitions whole; lowercase ones by
  `prosrc`.
- **Supabase adds storage tables on live** before the pinned CLI has them; the rehearsal now skips their data (#136).
- **Helpers each clone their own copy** (`/home/claude/eq-*`); the Building chat commits rule changes from a separate
  worktree of main so it never touches a helper's checkout.
- The working copy follows only `main` after a shallow clone: add `+refs/heads/*:refs/remotes/origin/*` to its fetch
  list so pushed branches show as tracked.
